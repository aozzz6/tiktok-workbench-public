## 2. 换机环境重建（必读，按顺序执行）

### 2.1 硬依赖

| 依赖 | 说明 |
|---|---|
| **本机代理 127.0.0.1:7897** | 所有 TikTok 抓取的硬依赖。代理客户端必须开机自启——代理死 = s1 degraded、s2 全量 `curl:7` 失败并拖 30 分钟才 FAIL |

| ffmpeg | faster-whisper 读音频依赖 |

### 2.2 Python 依赖（venv 内安装）

```
yt-dlp
curl_cffi            # 抓取统一走 chrome124 指纹
faster-whisper
ctranslate2
av==14.2.0           # ⚠️ 必须 pin！pip 默认装 av 19 与 faster-whisper 不兼容
openpyxl
```

### 2.3 faster-whisper 模型下载踩坑（v2 §5 原文保留，换机必踩）

1. 经代理下载 HF 模型报 502 → 改用 `HF_ENDPOINT=https://hf-mirror.com`
2. 镜像 + xet 加速报 401 → 必须加 `HF_HUB_DISABLE_XET=1`
3. Windows 下 snapshot 符号链接失效为 0 字节空文件 → 从 `blobs/` 按大小对应复制修复（勿重下）
4. 中文输出为繁体 → 生产转写加 `initial_prompt="以下是普通话的句子。"` 偏置简体

> 更省事的办法：直接拷贝旧机 HF 缓存目录（`~/.cache/huggingface/hub/models--Systran--faster-whisper-medium`）。

### 2.4 TikTok 抓取层关键约束（风控相关，勿改）

- 统一抓取层 `tiktok_fetch.py`：L1 scrapling → L2 curl_cffi 兜底，指纹 chrome124
- **不开 stealthy_headers**（会触发 TikTok 地区风控）
- 账号枚举：yt-dlp `@account` 直接提取已失效 → 两阶段：curl_cffi 抓主页解析 uid → `tiktokuser:{uid}`，uid 落盘缓存 `.uid_cache.json`
- 抓取限速 `RATE_LIMIT_SEC=5`（曾用 2s 连抓 30+ 条触发风控页被误判「itemStruct empty」）
- 「itemStruct 空 ≠ 下架」：冷却 90s 重抓，仍失败的走 `scripts/retry_scrape_failed.py --interval 8 --rounds 1`
- 抓取失败 → 自动慢速补抓已接入日更编排

## 3. 全链流程（pipeline.py）

### 3.1 执行 DAG（同 v2）

```
Step 0 前置校验 → Step 1 音频下载 ∥ Step 2 页面抓取 → Step 5 转写(CPU)
                       └→ Step 3/4 台账录入 → Step 6 翻译 → Step 7 回填 → Step 8 出单量 → Step 9 总结
```

### 3.2 命令

```
python pipeline.py --account {账号} --from 2026-10-01 --to 2026-10-08 \
    --xlsx "D:\1\对标账号\tiktok_对标.xlsx" \
    --steps s0_check s1_download s2_scrape s5_transcribe
```

### 3.3 门禁（gate.py，失败即停写 gate_report.json）

- `gate_download`：downloaded + skipped == matched 且 failed=[]
- `gate_scrape`：无 errors 且每条有 publish_time_gmt8
- `gate_transcribe`：全部完成且无 <30 字符疑似幻觉行
- `gate_backfill`：回读与预期逐条一致
- 全局重试上限：同一错误 ≥2 次失败即停链路报人

### 3.4 转写性能基准（本机实测）

faster-whisper medium / int8 / CPU：RTF=0.468（2.1× 实时），模型加载 4s。

**转写规则铁律**：
- 英文账号必须 `--lang en`——auto-detect 会把英文硬转成伪中文
- 纯 BGM 视频幻觉属正常，台账标注「（纯BGM，无口播）」
- **西语音频不能走英文流程**（vivi_ashop 09-29 两条爆款为西语音频，补译需西语→中文通道）

## 6. 日更编排（daily_update.py，每日 09:06 自动运行）

### 6.1 流程

`全局步骤 run_hot_monitor`（爆品监控）→ 逐账号增量（s0→s1→s2→s5）→ 台账写入 → 日报（邮件发 944535388@qq.com）

### 6.2 日更铁律（2026-10-05 实测踩坑后固化，违反必出假阴性）

1. **daily_update.py 调 pipeline.py 必须带 `--no-resume`**——pipeline_state 的 key 是 `{account}|{step}`（不含日期），跨日会把昨天的 ok=True 当成今天已完成而跳过 s0/s1/s2，导致当日完全没抓取却报 new=0（实测漏掉 11 条新视频）
2. **新增判定基准 = 台账实体**：manifest 视频集 − 台账 E 列已有 video_id，不用 last_run.new_ids 复用逻辑（当日重跑会吞掉新增）
3. **时间基准**：本机时区已是 UTC+8，`datetime.fromtimestamp(ts)` 即 GMT+8，**禁止再 +8h**（tk_audio_download/scrape 曾双重加 8h，导致台账发布时间整体偏晚 8 小时；已修正为显式 `timezone(timedelta(hours=8))` 并回填存量）
4. 爆品监控兜底：cookie 缺失 = skipped、快照 0 源 = WARN、EXCEPTION 不阻断日更
5. 日更卡长（>15 分钟无日志更新）→ 先探测代理端口 127.0.0.1:7897 监听（bash /dev/tcp），确认代理死即止损中止，不空等；恢复 = 启动代理后重跑（--no-resume + 台账基准自动补缺口）

## 8. 落盘与终验铁律（editor/openpyxl 事故沉淀）

1. **报告正确 ≠ 磁盘正确**：台账写入后必须磁盘终验（openpyxl 重新 load 直读），不轻信子代理/会话内回读——实测 sheet-agent 曾漏报整个 sheet 且意译商品名
2. **磁盘终验必须核对 sheet 数量与名单**，不只行数——编辑器会话可能只加载磁盘文件的部分 sheet（openpyxl 后建的最后一个 sheet 尤其危险），save_file 会把会话状态整体覆写磁盘，未加载的 sheet 直接丢失
3. sheet 丢失恢复流程：`close_file` 释放陈旧会话 → openpyxl 重建/写盘 → `resolve_local_excel` 重开会话（确认 sheet 齐全）→ 再 save_file 验证存活
4. 台账写入零值格必须**显式写 0**（省略会让单元格保留旧值）；补写清单程序化生成，禁手抄（手抄曾两次引入笔误）
5. 凡 openpyxl 落盘后必须走 close→reopen 与编辑器会话同步
6. 写入前核对磁盘真实路径（用户会移动文件，editor 会话绑定打开时路径，移动后写入会丢）
