## 四、核心 BUG：ctranslate2 本机崩溃 + 止损方案

**现象**：`WhisperModel(...)` / `Translator(...)` 构造即 `access violation`
（SIGSEGV 139）。medium/tiny 都崩、import 正常、`OMP_NUM_THREADS=1` 无效、
`CT2_FORCE_CPU_ISA=AVX2/SCALAR` 无效（4.7.0 未生效）、出沙箱无效、
实体化符号链接后仍崩。

**根因**：本机 CPU = Intel Core i5-12400（Family 6 Model 151，AVX-512 平台），
ctranslate2 官方 Windows wheel 的 native 推理器在该平台构造时 access violation。
非模型文件、非符号链接、非沙箱问题。

**止损（确定性方案）**：转写切 openai-whisper + torch（PyTorch CPU 路线）。
- 已给 `scripts/batch_transcribe_fw.py` 加 `--backend {faster,openai}`（默认
  faster，**非破坏性**，保留原 stdout JSON 契约与转写文件格式）。
- 已给 `pipeline.py` step5 + main 加 `--backend` 透传。
- 本机运行一律 `--backend openai`（faster 后端保留在代码里，换到非 AVX-512
  机器可用回）。
- 4.7.0 若要用，还需 `site-packages/_rocm_sdk_core/bin` +
  `_rocm_sdk_libraries_custom/bin` 两个空目录（已建）。
