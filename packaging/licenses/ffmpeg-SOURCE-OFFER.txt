FFmpeg corresponding-source offer — GPLv3 §6(b) written offer
================================================================

Applies to: the portable package `tiktok-workbench-<version>-full.zip` and
`tiktok-workbench-<version>-slim.zip`.
This file is part of the license bundle that ships inside the package under
`<pkg>\licenses\`. The full license text is `ffmpeg-COPYING.GPLv3.txt` in the
same folder.

------------------------------------------------------------------------------
1. What we distribute
------------------------------------------------------------------------------

The package ships a prebuilt Windows x64 FFmpeg:

    ffmpeg version 9.0.2-essentials_build-www.gyan.dev

    files:   <pkg>\ffmpeg\bin\ffmpeg.exe
             <pkg>\ffmpeg\bin\ffprobe.exe
    license: GPLv3
    build:   --enable-gpl --enable-version3 --enable-static
             (the build's own README.txt says: License: GPL v3)
    source:  FFmpeg commit 946fcce07b
             https://github.com/FFmpeg/FFmpeg/commit/946fcce07b

Because the build is `--enable-static`, the third-party libraries listed in
§3 are statically linked into those two executables, so they are distributed
as part of the same binaries and are covered by the same GPLv3 obligation.

The workbench calls `ffmpeg.exe` / `ffprobe.exe` as **separate spawn
processes** (Python `subprocess`) and does **not link** them with the
project's own code — see §6. A second, different FFmpeg copy is loaded inside
the process by PyAV; it is described in `PYAV-FFMPEG-SOURCE.txt` and is
included in the scope of this offer (see §2).

(i) **Validity — three (3) years.**

     (The same channel also works if a download link in §4 ever breaks.)

5. How to download and verify the source
------------------------------------------------------------------------------

Canonical FFmpeg release tarballs (what the asset names above come from):

    curl -L -O https://ffmpeg.org/releases/ffmpeg-9.0.2.tar.xz
    curl -L -O https://ffmpeg.org/releases/ffmpeg-7.1.tar.xz

If a release tarball is unavailable, the exact commit/tag archive is
equivalent (GitHub produces it on demand):

    # CLI FFmpeg — the commit named by the build's own README
    curl -L -o ffmpeg-9.0.2-source.tar.gz \
      https://github.com/FFmpeg/FFmpeg/archive/946fcce07b.tar.gz

    # the FFmpeg inside PyAV — release tag n7.1
    curl -L -o ffmpeg-7.1-source.tar.gz \
      https://github.com/FFmpeg/FFmpeg/archive/refs/tags/n7.1.tar.gz

Verification:

  * `SHA256SUMS.txt` in the same release lists the SHA-256 of every asset;
    after downloading, compare with `Get-FileHash -Algorithm SHA256` (Windows)
    or `sha256sum` (Unix).
  * ffmpeg.org also publishes `<tarball>.sha256` next to each release tarball.
  * The commit id `946fcce07b` is what the distributed build's README.txt
    names as its source; it is quoted in §1.

This machine did **not** download the two tarballs (they are ~10–20 MB each).
The download and checksum verification is a release-time step and must be done
before the release is published.

------------------------------------------------------------------------------
6. How the workbench uses ffmpeg (no linking)
------------------------------------------------------------------------------

The workbench runs `ffmpeg.exe` / `ffprobe.exe` as **separate processes** and
communicates only through command-line arguments and files. The project's own
code does **not** link against FFmpeg, does not include FFmpeg headers, and is
not a derivative work of FFmpeg. ffmpeg is found on `PATH` (the packaged
`_setenv.bat` puts `<pkg>\ffmpeg\bin` first).

The separate FFmpeg copy shipped inside the PyAV wheel is a different case: it
is loaded **in the same process** by the `av` Python extension (used by
faster-whisper to decode audio). It is described, with its version and source
details, in `PYAV-FFMPEG-SOURCE.txt`.

7. What this offer does not cover
------------------------------------------------------------------------------

  * The project's own source code: MIT — see `LICENSE` at the package root.
  * Python packages bundled in the package: each keeps its own license; the
    package list is `licenses\PYTHON-PACKAGES.txt`, and the original metadata
    (`*.dist-info`) is kept under `python\Lib\site-packages\`.
  * Microsoft Visual C++ runtime DLLs: Microsoft's redistributable terms; see
    `THIRD_PARTY_NOTICES.md`.
  * The `av` python wheel itself: BSD-3-Clause (PyAV), separate from the
    FFmpeg binaries it bundles.
